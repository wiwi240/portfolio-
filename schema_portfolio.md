# Schema Portfolio

## Objectif

Le portfolio doit faire trois choses:

1. Montrer ce que je sais faire
2. Montrer comment je reflechis
3. Donner envie de me contacter

Pour un profil developpeur junior a intermediaire, il ne faut pas faire un site vitrine vide. La priorite est de montrer des preuves concretes a travers des projets serieux, lisibles et bien expliques.

## Cible

- Recruteur
- client
- lead developer
- equipe produit ou technique

Le visiteur passe souvent entre 30 secondes et 2 minutes sur le portfolio. L ordre des sections doit donc repondre rapidement aux questions suivantes:

1. Qui est cette personne ?
2. Que sait-elle construire ?
3. Est-ce que son niveau semble solide ?
4. Est-ce que j ai envie de la contacter ?

## Ordre final recommande

1. Hero
2. Projets
3. Stack / competences
4. Process de travail
5. About Me
6. GitHub / experience
7. Contact

## 1. Hero

### Role

Le hero doit repondre en 5 secondes a:

- qui je suis
- ce que je fais
- ce qui me differencie

### Structure attendue

- nom + titre
- phrase de positionnement
- CTA clairs

### Exemple de contenu

- `William MAHI`
- `Developpeur Fullstack JavaScript / TypeScript`
- `Je concois des applications web et desktop modernes avec React, TypeScript et des architectures pensees pour etre maintenables.`

Ou, si le positionnement est plus oriente produit / dev tools:

- `Je cree des outils orientes developpeurs, local-first et assistes par IA.`

### CTA recommandes

- Voir mes projets
- Me contacter
- GitHub
- LinkedIn
- CV PDF

### A eviter

- `Passionne d informatique depuis toujours`
- gros pave de texte
- animations inutiles

## 2. Projets

### Role

C est la section la plus importante du portfolio.

Les projets doivent representer environ 60 a 70 pour cent de la valeur percue du site.

Un bon portfolio ne repose pas sur un discours, mais sur une demonstration.

### Principe

Qualite superieure a quantite.

Mieux vaut:

- 3 projets solides

que:

- 10 a 12 petits projets generiques

### Structure de chaque projet

Chaque projet doit contenir:

#### A. Preview

- image
- capture
- video
- mockup produit

Le visiteur doit voir rapidement le produit.

#### B. Probleme

Pourquoi ce projet existe ?

Exemple:

`Outil visant a reduire la dependance des developpeurs aux IA en guidant la reflexion plutot qu en donnant directement la solution.`

#### C. Solution

- approche produit
- choix d interface
- architecture generale

#### D. Stack technique

Exemples:

- React
- TypeScript
- Vite
- Prisma
- PostgreSQL
- Tauri
- SQLite

#### E. Challenges techniques

C est un point majeur. C est ce qui montre le niveau reel.

Exemples:

- mise en place d une architecture monorepo avec Turborepo
- organisation automatique de notes via relations semantiques
- gestion local-first avec synchronisation differee
- modelisation de donnees propre
- gestion d etat complexe

#### F. Liens

- Demo
- GitHub
- Documentation

### Projets a prioriser pour ce profil

- Rubber Duck
  outil pedagogique oriente developpeur
- app memoire technique type Obsidian local-first
- site tattoo si l execution UI est propre et production-ready

## 3. Stack / Competences

### Role

Montrer les outils maitrises sans tomber dans la liste decorative de logos.

### Principe

Il faut eviter l effet:

- `je connais 45 technos`

La credibilite vient de la selection et de la hierarchisation.

### Structure recommandee

#### Frontend

- React
- TypeScript
- Vite
- Tailwind

#### Backend

- Node.js
- Express
- NestJS si reellement maitrise

#### Database

- PostgreSQL
- Prisma
- SQLite

#### Tooling

- Git
- Turborepo
- pnpm
- Docker si usage reel

### Niveaux de maitrise possibles

#### Maitrise forte

- React
- TypeScript
- Vite

#### Confortable

- Node.js
- Prisma
- PostgreSQL

#### En apprentissage

- Rust
- Tauri

Cette approche est plus credible qu une liste plate.

## 4. Process de travail

### Role

Section tres utile pour se differencier.

Elle montre que je ne fais pas seulement du code, mais que je sais structurer un projet.

### Exemple de deroulement

1. Comprendre le probleme
2. Poser une architecture technique
3. Construire un MVP rapidement
4. Iterer sur l UX/UI
5. Stabiliser, optimiser, securiser

### Ce que cette section doit transmettre

- clarte de raisonnement
- logique produit
- priorisation
- capacite a aller vers quelque chose de maintenable

## 5. About Me

### Role

Donner du contexte humain et professionnel sans casser le rythme du portfolio.

### Format

Court, direct, utile.

### Exemple

`Developpeur Fullstack oriente JavaScript/TypeScript. J aime construire des applications utiles, avec une attention particuliere portee a l architecture, l experience developpeur et les outils productifs.`

### Themes possibles

- architecture propre
- outils dev
- IA
- local-first
- UX technique

## 6. GitHub / Experience

### GitHub

Si le GitHub est propre, il faut le montrer.

Avant cela:

- nettoyer les repos inutiles
- retirer les projets abandonnes peu valorisants
- verifier qu aucun secret n a ete commit
- epingler seulement les meilleurs projets

### Experience

Si experience professionnelle faible ou absente, les projets peuvent compenser.

Exemple de formulation:

- `Developpeur Fullstack — Projets personnels`
- `2025 - Aujourd hui`
- `Applications React/TypeScript`
- `Architecture monorepo`
- `Outils orientes developpeurs`

## 7. Contact

### Role

Fermer le parcours avec une action claire.

### Contenu

- email
- LinkedIn
- GitHub
- CV

### CTA final

- `Disponible pour missions, collaboration ou opportunites developpeur.`

## Priorite editoriale

Pour ce profil, les projets doivent dominer le portfolio.

Le site ne doit pas ressembler a:

- une vitrine de technos
- une page de slogans
- un empilement de sections sans preuves

Il doit plutot donner cette impression:

- la personne sait construire
- la personne sait expliquer
- la personne a de bonnes idees produit
- la personne merite un entretien ou une prise de contact

## Regles de fond

- Montrer des preuves avant les promesses
- Garder un texte court et dense
- Faire passer le projet avant l ego
- Eviter les formulations generiques
- Donner de la place aux challenges techniques
- Prioriser la lisibilite et la credibilite
